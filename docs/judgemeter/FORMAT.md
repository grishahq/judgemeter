# Record and statistical contract (schema 1.0)

Input: nonempty JSON array. Every record requires `case_id`, `judge` (nonempty strings), `trial` (nonnegative integer), `input`, `output` (finite JSON values). `score` is optional. Additional JSON metadata is preserved. Inputs/outputs are canonicalized by sorting object keys; arrays remain ordered. Changed fixed case input/output or duplicate judge/case/trial rejects the entire dataset. Case IDs must distinguish different expected tasks even if display prompts are similar.

Scores: finite numeric [0,1] are valid. JSON booleans, strings and out-of-range numbers are invalid, not coerced. Missing field and null are missing. JSON NaN/Infinity are rejected by the CLI; Python API nonfinite scores are invalid and serialized as explicitly annotated text. Original JSON file is never overwritten. JSON reports preserve all submitted records, including invalid values. Non-JSON metadata rejects input. Absent trial rows are unknowable; include explicit null scores to count missing evaluations. Gaps only affect adjacency.

For a case with n valid scores, categorize each score as pass if >= threshold, otherwise fail. Let category counts be n0 and n1. Valid pairs = n(n-1)/2; agreeing pairs = n0(n0-1)/2 + n1(n1-1)/2. Pair agreement = agreeing/valid pairs, or null when n<2. Majority fraction = max(n0,n1)/n; it is not majority-vote accuracy. Mean uses raw valid numeric scores. Numeric variation inside a category does not change verdict agreement.

Flip counts use consecutive integer trial IDs with valid scores at both ends, sorted numerically. A flip is a category change; missing/invalid scores and gaps break adjacency. Flip rate = flips/adjacent valid pairs, or null with zero adjacent pairs. It is an order-dependent descriptive diagnostic, distinct from all-pairs agreement.

Macro agreement = equal-weight mean of sufficiently sampled case agreements. Summary lists insufficient-case count. Pooled agreement = total agreeing pairs / total valid pairs. Missing rate = missing/records, invalid rate = invalid/records, unusable rate = (missing+invalid)/records. Comparisons use candidate minus baseline, equal weight per matched case with sufficient samples in both judges; disclose unmatched/insufficient cases. Default descriptive comparisons allow unequal trial counts but do not imply equal precision. CI drop gates fail incomplete coverage. No test of statistical significance.

Fleiss kappa uses complete equal-size cases only; v0.1 refuses partial cases rather than silently selecting cases or imputing scores. For >=2 cases and >=2 ratings each, observed Pbar is the mean case pair agreement. Marginal p is total passes / total valid ratings. Pe=p²+(1-p)² and kappa=(Pbar-Pe)/(1-Pe). Constant marginals make kappa undefined. Negative kappa is possible. Ratings are assumed exchangeable with the same categories; prevalence affects kappa and dependence can weaken interpretations. A valid formula does not establish that your trial sampling design justifies inference.

Threshold must be finite [0,1], defaults to 0.5. Report contains schema_version, threshold, data_kind, assumptions, judges, raw_records and optional comparison/gate. `data_kind` is user_supplied unless generated by the explicit demo command; raw-record provenance must identify measured versus synthetic inputs.

No human labels: no accuracy, calibration or correctness metric. No automatic model calls, no Braintrust export importer in v0.1. No credential required. Judge names are user claims; fixed input/output checks do not verify model/rubric versions.
